01

Conceitos fundamentais

recap▶
Objetivo: a base necessária pra entender o resto do review — sem isso, o código da aula é só sintaxe decorada.
TermoO que é
STAC (SpatioTemporal Asset Catalog)Padrão aberto que descreve imagens de satélite (data, área, sensor, nuvens) de forma uniforme, independente do provedor (INPE, AWS, Microsoft). Permite buscar por metadado antes de baixar qualquer pixel.
Bbox (bounding box)Retângulo (min-lon, min-lat, max-lon, max-lat) que delimita a área de interesse — o filtro espacial mais básico.
CRS / EPSGSistema de referência de coordenadas. EPSG:4326 (lat/lon, WGS84) é o padrão de GPS; cada cena pode estar num CRS projetado diferente, por isso é preciso reprojetar o bbox antes de recortar.
Banda espectralUm satélite captura várias imagens (bandas), cada uma de uma faixa do espectro (azul, verde, vermelho, infravermelho próximo/NIR). Combinar bandas revela informação invisível a olho nu.
Reflectância de superfícieFração da luz solar refletida pela superfície, já corrigida de efeitos atmosféricos — o valor "limpo" de cada pixel, o que sustenta comparar cenas de datas diferentes.
NDVI / NDWI / EVIÍndices espectrais — contas entre bandas que traduzem sinal bruto em algo interpretável (vigor de vegetação, presença de água, vegetação corrigida de ruído atmosférico).
ThresholdingCortar um valor contínuo (ex: NDVI de -1 a 1) em categorias discretas por faixa de valor.
Leitura por janela (Window)Ler só um pedaço retangular de um raster gigante em vez do arquivo inteiro.
02

Busca STAC como API filtrável

código vs. teoria▶
Objetivo: entender a busca STAC como uma query paramétrica, não uma navegação manual por site de provedor.

O padrão usado nos dois notebooks é client.search(bbox=..., datetime=..., collections=..., query={"eo:cloud_cover": {"lt": 15}}) — uma consulta espaço-temporal com filtros compostos, equivalente a uma query de backend, só que sobre um catálogo geoespacial padronizado.

client = Client.open("https://data.inpe.br/bdc/stac/v1/")
item_search = client.search(
    bbox=[-45.96, -11.89, -45.42, -11.53],
    datetime='2024-08-01/2025-07-31',
    collections=['CB4-MUX-L4-SR-1'],
    query={"eo:cloud_cover": {"lt": 15}}
)
Filtrar por metadado antes de baixar evita transferir gigabytes de cena majoritariamente encoberta por nuvem que seria descartada de qualquer forma.
03

Leitura por janela (Window)

código vs. teoria▶
Objetivo: entender RAM como restrição de projeto, e como o código contorna isso.

Uma banda em resolução total tem ~51 milhões de pixels. O notebook mede isso na prática com uma função check_memory() reaproveitada, chamada antes/depois de cada operação pesada — RAM cai de "carregar 3 bandas inteiras" pra "ler uma janela de 500×500" ao reprojetar o bbox de interesse (EPSG:4326 → CRS da cena) e ler só essa fatia via rasterio.windows.from_bounds.

def read_window(uri, bbox, masked=True):
    with rasterio.open(uri) as src:
        transformer = Transformer.from_crs("EPSG:4326", src.crs, always_xy=True)
        minx, miny = transformer.transform(bbox[0], bbox[1])
        maxx, maxy = transformer.transform(bbox[2], bbox[3])
        window = from_bounds(minx, miny, maxx, maxy, src.transform).round_offsets().round_lengths()
        return src.read(1, window=window, masked=masked)
04

Normalização: min-max vs. percentil

código vs. teoria▶
Objetivo: perceber a evolução do próprio código do professor entre os dois notebooks.

A primeira versão de normalize() (RS-STAC.ipynb) usa min/max puro — sensível a outliers, um pixel de ruído estica toda a escala. A versão usada no caso Brumadinho (RS-Image_Processing.ipynb) troca para stretch() por percentil (2–98), mais robusta a valores extremos.

MétodoFórmulaProblema que resolve
Min-max(x - min) / (max - min)Simples, mas 1 pixel de ruído distorce toda a escala
Percentil (2-98)(x - p2) / (p98 - p2), com clipIgnora os extremos — mais robusto a outliers/ruído de sensor
05

Índices espectrais

código vs. teoria▶
Objetivo: calcular e interpretar NDVI, NDWI e EVI — aplicados ao caso real da barragem de Brumadinho.
ÍndiceFórmulaDetecta
NDVI(NIR − Red) / (NIR + Red)Vigor de vegetação
NDWI(Green − NIR) / (Green + NIR)Água / umidade
EVIG×(NIR−Red)/(NIR+C1×Red−C2×Blue+L)Vegetação, corrigido de efeito atmosférico/solo
def calc_ndvi(nir, red):
    return (nir - red) / (nir + red)

def calc_ndwi(green, nir):
    return (green - nir) / (green + nir)

def calc_evi(nir, red, blue, G=2.5, C1=6, C2=7.5, L=1):
    return G * (nir - red) / (nir + C1 * red - C2 * blue + L)
06

Classificação por limiar e diferença temporal

código vs. teoria▶
Objetivo: entender como o rompimento da barragem de Brumadinho (25/01/2019) foi detectado a partir de imagem de satélite.

classify_ndvi() corta o índice contínuo em 3 classes, calibrado pelo histograma real da cena (não um valor arbitrário): < 0.2 solo/água/urbano, 0.2–0.45 vegetação fraca, ≥ 0.45 vegetação vigorosa.

A detecção de impacto é só ndvi_depois - ndvi_antes, com o resultado mais forte em diff < -0.3 — perda de vegetação onde a lama de rejeitos passou.

Mesma lógica aplicada ao NDWI revela o possível assoreamento do Rio Paraopeba.
07

Insights — Engenharia de Produção / Back-End

aplicação▶
Objetivo: conectar os padrões técnicos da aula ao seu repertório de Eng. Produção.

RAM como restrição de capacidade (bottleneck)

check_memory() monitorando RAM antes/depois de cada operação é, na prática, monitoramento de um recurso gargalo — a leitura por janela é a mitigação: processar só o necessário, no momento necessário. Equivalente direto a JIT/eliminação de desperdício do Lean, aplicado a I/O de dados em vez de estoque físico.

Duplicação de código — dívida técnica real

check_memory() e uma variação de normalize() aparecem copiadas nos dois notebooks — já divergiram uma vez (min-max virou percentile-stretch numa cópia e não na outra). Ação concreta: extrair pra um módulo compartilhado (aprendizado/utils/raster.py).

Limiar calibrado por dado real — paralelo com limites de controle

Os limiares do NDVI (0.2 / 0.45) foram lidos do histograma real da cena antes de classificar — mesmo princípio de definir limites de controle (SPC) a partir da distribuição observada, não de um valor teórico genérico.

Diff antes/depois como análise de causa isolada

Subtrair duas datas da mesma variável, área e sensor isola o efeito do evento de outras fontes de variação — o mesmo racional de um estudo antes/depois em melhoria de processo.
