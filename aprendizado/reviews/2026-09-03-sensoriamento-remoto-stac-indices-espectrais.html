Resumo executivo

A aula cobriu o ciclo completo de acesso a imagens de satélite via STAC (Spatial Temporal Asset Catalogue): buscar cenas por área/data/nuvens no catálogo do INPE (Brazil Data Cube), ler bandas específicas com rasterio sem baixar a imagem inteira, montar composições RGB e falsa-cor, e servir o resultado num painel interativo com leafmap.

O segundo notebook aplica tudo isso a um caso real: o rompimento da barragem de Brumadinho (25/01/2019). Calcula NDVI, NDWI e EVI antes e depois do desastre, classifica a vegetação por limiar, e usa a diferença entre datas para visualizar o impacto — perda de vegetação e assoreamento do Rio Paraopeba.

Fio condutor técnico da aula: gerenciamento de recursos (RAM) como restrição de projeto — resolvida com leitura por janela (window) em vez de carregar a imagem inteira.

Conceitos fundamentais

Base necessária para entender o resto do review — sem isso, o código da aula é só sintaxe decorada.

STAC (SpatioTemporal Asset Catalog)

Padrão aberto que descreve imagens de satélite (data, área, sensor, nuvens) num formato uniforme, independente de quem forneceu a imagem (INPE, AWS, Microsoft). Permite buscar por metadado antes de baixar qualquer pixel — como um índice de biblioteca em vez de vasculhar estante por estante.

Bbox (bounding box)

Retângulo definido por 4 coordenadas (min-lon, min-lat, max-lon, max-lat) que delimita a área de interesse. É o filtro espacial mais básico: "eu só quero o que está dentro desse retângulo".

CRS / EPSG (Sistema de Referência de Coordenadas)

Define como coordenadas (números) correspondem a posições reais na Terra. EPSG:4326 (lat/lon, WGS84) é o padrão universal para GPS; cada cena de satélite pode estar num CRS projetado diferente — por isso é preciso reprojetar o bbox antes de recortar a imagem.

Banda espectral

Um satélite não captura uma "foto" — captura várias imagens (bandas), cada uma de uma faixa específica do espectro eletromagnético (azul, verde, vermelho, infravermelho próximo/NIR, etc). Combinar bandas diferentes revela informação invisível a olho nu.

Reflectância de superfície

Fração da luz solar que a superfície reflete de volta ao sensor, já corrigida de efeitos da atmosfera. É o valor "limpo" de cada pixel — o que sustenta comparar duas cenas de datas diferentes com confiança.

NDVI / NDWI / EVI

Índices espectrais: contas simples entre bandas que traduzem sinal bruto em algo interpretável. NDVI mede vigor de vegetação, NDWI mede presença de água/umidade, EVI é uma versão do NDVI corrigida para ruído atmosférico e de solo.

Thresholding (classificação por limiar)

Transformar um valor contínuo (ex: NDVI de -1 a 1) em categorias discretas (ex: "sem vegetação", "vegetação fraca", "vegetação vigorosa") cortando por faixas de valor.

Leitura por janela (Window)

Ler só um pedaço retangular de um arquivo raster gigante, em vez do arquivo inteiro — a imagem pode ter 7000×7000 pixels, mas só interessa uma fração dela.

Análise técnica: código vs. teoria

1. Busca STAC como API de consulta filtrável

O padrão client.search(bbox=..., datetime=..., collections=..., query={"eo:cloud_cover": {"lt": 15}}) é uma API de consulta espaço-temporal com filtros compostos — equivalente a uma query paramétrica de backend, só que sobre um catálogo geoespacial padronizado ao invés de um banco relacional.

2. Leitura por janela (Window) em vez de imagem completa

Uma banda em resolução total tem ~51 milhões de pixels. A função read_bbox/read_window reprojeta o bbox de interesse (EPSG:4326 → CRS da cena) e lê só essa fatia via rasterio.windows.from_bounds. O notebook mede isso na prática com check_memory() antes/depois — RAM cai de "carregar 3 bandas inteiras" para "ler uma janela de 500×500".

3. Normalização: min-max vs. contraste por percentil

A primeira versão de normalize() usa min/max puro (sensível a outliers — um pixel de ruído estica toda a escala). A versão usada no caso Brumadinho troca para stretch() por percentil (2–98), mais robusta. É a mesma imagem processada com um método mais maduro — vale registrar por que a troca foi feita.

4. Índices espectrais como métricas derivadas

NDVI = (NIR-RED)/(NIR+RED), NDWI = (GREEN-NIR)/(GREEN+NIR), EVI (corrige efeito atmosférico/solo). São razões normalizadas entre bandas — o mesmo princípio de construir um indicador composto a partir de variáveis brutas.

5. Classificação por limiar e diferença temporal

classify_ndvi() corta o índice contínuo em 3 classes (solo/água/urbano < 0.2; vegetação fraca 0.2–0.45; vegetação vigorosa ≥ 0.45), calibrado pelo histograma real da cena — não um valor arbitrário. A detecção de impacto do desastre é só ndvi_depois - ndvi_antes, com o resultado mais forte em diff < -0.3.

Insights práticos — Engenharia de Produção / Back-End

RAM como restrição de capacidade (bottleneck)

O check_memory() monitorando uso de RAM antes/depois de cada operação é, na prática, monitoramento de um recurso gargalo — a mesma lógica de identificar e proteger o recurso restritivo num processo (Teoria das Restrições). A leitura por janela é a ação de mitigação: processar só o que é necessário, no momento em que é necessário — equivalente direto a JIT/eliminação de desperdício do Lean, aplicado a I/O de dados em vez de estoque físico.

Duplicação de código entre notebooks — dívida técnica real

check_memory() e uma variação de normalize() aparecem copiadas e coladas nos dois notebooks. Do ponto de vista de back-end isso é falta de DRY: cada aula reescreve as mesmas funções utilitárias. Ação concreta: extrair para um módulo compartilhado (ex: aprendizado/utils/raster.py) e importar — reduz risco de as versões divergirem silenciosamente (já divergiram uma vez: min-max virou percentile-stretch numa cópia e não na outra).

Limiar calibrado por dado real, não fixo — paralelo com limites de controle

Os limiares do NDVI (0.2 / 0.45) foram lidos do histograma real da cena antes de classificar, não hardcoded a priori — o mesmo princípio de definir limites de controle (SPC) a partir da distribuição observada do processo, não de um valor teórico genérico.

Diff antes/depois como análise de causa-efeito isolada

Subtrair duas datas da mesma variável, mesma área, mesmo sensor, isola o efeito do evento (rompimento da barragem) de outras fontes de variação — é o mesmo racional de um estudo antes/depois em melhoria de processo: manter tudo constante exceto a variável de interesse para poder atribuir a mudança a uma causa específica.
